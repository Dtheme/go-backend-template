# 阅读指南：按角色的顺序与每篇对应的模板文件

本篇只做两件事：按角色给出阅读顺序，列出每篇会带着打开哪些模板文件。各章讲什么见「go-backend-template｜文档导航」，命令、目录、字段取值见「速查表」。

## 按角色的阅读顺序

五种进入方式。顺序里写的是篇名前缀，每个前缀只对应一篇，完整标题见下一节。

| 角色 | 目标 | 建议顺序 |
| --- | --- | --- |
| 初次接手 | 弄清模板守住了什么、谁在守、`1.0.0` 为什么停在 `verifying` | 总览 → Rules 落地 → Spec 落地 → 版本开发工作流 → 验证闭环 → Command 落地 → 工程骨架 |
| 新建业务工程 | 从模板复制出工程，按七个 Step 做完第一个版本 | 04-初始化与资产同步 Skills → 工程骨架 → 代码规范与日常修改 → spec-init → 版本开发工作流 → API 契约设计 → 测试分层 → 验证闭环 → 07-Memory |
| 接入存量工程 | 给已有 Go 工程补上 Specs 目录、行为准则与门禁 | 04-初始化与资产同步 Skills → Rules 落地 → 03-AI Rule → 01-Spec 文档 → Command 落地 → Skill 落地 → 第三方 Skill → 08-Harness |
| 改工作流 | 调整 Step、门禁、Skill、Subagent、Hook 或 MCP 的边界 | Rules 落地 → 03-AI Rule → 版本开发工作流 → Command 落地 → Subagent 与 Hook 落地 → 06-Skill → 07-Memory → MCP 落地 |
| 启用 Graph | 理解证据失效判定，再用 `spec-graph` 编排一个版本 | Spec + Graph 理论 → Spec + Graph 落地 → 02-Graph → 05-Graph 编排与 API 验收 Skills → 验证闭环 → spec-init |

## 先跑命令，再信文档

接手模板先重跑四条门禁，命令含义见「速查表」，`1.0.0` 的完整结果与它为什么仍停在 `verifying` 见「总览」与「验证闭环」。

```sh
make check
make test-integration
make test-race
make smoke
```

`docs/spec-graph/理论.md` 与 `docs/spec-graph/落地.md` 是 Graph 两篇在工程内的速查版本，与文档对不上时以模板内文件为准。
