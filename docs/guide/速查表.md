# 速查表

模板仓库速查：命令、目录、Spec 文件、Skill、字段与接口的位置和一句话用途；内容以仓库为准。文档阅读顺序见 阅读指南。

## 一、命令
| Makefile 目标 | 作用 | 何时跑 |
| --- | --- | --- |
| `run` | `go run ./cmd/api`，默认 `:8080` | 本地调试、用户验收前 |
| `build` | 编译到 `bin/api` | 需要真实二进制时 |
| `test` | `go test ./...` | 改代码后随时 |
| `test-integration` | `go test -tags integration ./...` | 接口或跨层改动后，必需门禁 |
| `test-race` | `go test -race ./...` | 并发改动后 |
| `check` | `vet` + `test` + `spec-check` + `gofmt -l` 为空 | 提交前、Step 6.1 自验，必需门禁 |
| `spec-check` | `go run ./cmd/spec-check`，核对必需文件与章节、符号链接、版本目录、Feature ID、交付状态、Postman 集合 | 只查文档一致性时单跑 |
| `spec-init` | `sh scripts/spec-init.sh $(VERSION)` 生成版本技术方案，缺 `VERSION` 退出 2 | 人工需求已存在、进入 Step 4 |
| `fmt` | `gofmt -w .` | 格式检查报错后 |
| `vet` | `go vet ./...` | 单独排查可疑写法 |
| `lint` | `golangci-lint run --timeout 5m`，未安装跳过 | 可选，提交前 |
| `vuln` | `govulncheck ./...`，未安装跳过 | 可选，依赖变化后 |
| `smoke` | `bash scripts/smoke.sh`，编译真实二进制并 curl | 发布候选自验 |
| `clean` | `rm -rf bin` | 清理构建产物 |

入口 `go run ./cmd/spec-graph`；`--root <dir>` 只在子命令之前解析，版本号必须形如 `x.y.z`。

| spec-graph 子命令 | 作用 |
| --- | --- |
| `init <version>` | 创建 `Specs/technical/<version>/graph.json`，阶段 `planning` |
| `status <version> [--json]` | 只读；重算摘要，输出阶段、漂移、finding 计数、各 kind 最新证据、交付状态 |
| `record <version> --kind <k> --exit <n> [--log <path>] [--expect-revision <n>]` | 追加证据并绑定当前摘要；kind 限 `check`、`test-integration`、`test-race`、`smoke`、`api-verify`、`review` |
| `finding <version> --id <id> --severity <P0..P3> --status <s> [--note <text>] [--expect-revision <n>]` | 新建或推进 finding；流为 `open -> accepted` 或 `rejected`、`accepted -> fixed`、`fixed -> verified` |
| `event <version> <type> [--id <id>] [--expect-revision <n>] [--at <RFC3339>]` | 推进阶段，守卫在锁内判定 |
| `check <version>` | 只读核对 graph 与技术方案交付状态，问题按 `路径: 消息` 打印 |

| 退出码 | 触发条件 |
| --- | --- |
| 0 | 成功；`check` 无问题 |
| 1 | `check` 报告问题；graph.json 不存在；其他读写或解析错误 |
| 2 | 用法错误：子命令、版本号、事件类型、`--kind`、`--severity`、`--status` 不合法，缺必填 flag，多余参数，`--log` 读不到 |
| 3 | 守卫拒绝或冲突：非法转换、finding 流不允许、锁被占用、`--expect-revision` 不符、`init` 时文件已存在 |

## 三、Spec 四件套
| 文件 | 维护方 | 什么时候改 |
| --- | --- | --- |
| `Specs/requirements/需求模版.md` | 人工 | 需求写法约定变化时；新版本需求从此复制到 `{version}/需求.md` |
| `Specs/requirements/协议与数据.md` | 人工 | 通用约定、错误码、对接方约束变化时；AI 只读 |
| `Specs/technical/技术方案模版.md` | AI | `make spec-init` 由它生成 `{version}/技术方案.md`；模版章节调整时改 |
| `Specs/technical/技术讲解.md` | AI | 版本开发结束（Step 7）和日常代码修改后 |

## 五、Subagent 与 Hook
| 项 | 范围或配置 | 用途 |
| --- | --- | --- |
| `.claude/agents/spec-reviewer.md` | `Read, Grep, Glob` | 只读审查需求覆盖、实现正确性、生产风险；不改文件不跑命令 |
| `.claude/agents/spec-implementer.md` | `Read, Grep, Glob, Edit, Write, Bash` | 按主会话给定切片测试先行实现，只跑 focused 测试 |
| `.claude/settings.json` `hooks.PostToolUse` | matcher `Edit\|Write` | 执行 `"$CLAUDE_PROJECT_DIR"/scripts/check-format.sh` |
| `.claude/settings.json` `permissions.allow` | 预授权 | `go`、`gofmt`、`make`、`curl`、`git`、`bash`、`lsof`、`shasum` |
| `.codex/config.toml` | Codex 无 Hook 与 Subagent | 格式检查靠 `make check`，审查按 spec-reviewer 正文另开会话 |

## 六、关键字段
技术方案「## 交付状态」YAML 块由 `spec-check` 核对：`stage: delivered` 要求 `user_acceptance: confirmed` 且 `review` 为 `pass` 或 `not_required`。

| 键 | 取值 | 含义 |
| --- | --- | --- |
| `stage` | `planning` \| `implementing` \| `verifying` \| `delivered` | 方案确认后 `implementing`，进入 Step 6 改 `verifying`，Step 7 回写后 `delivered` |
| `user_acceptance` | `pending` \| `confirmed` | 用户在 Step 6.2 明确确认后才写 `confirmed` |
| `review` | `not_required` \| `pending` \| `changes_required` \| `pass` | 独立审查结论 |

`graph.json` 只能由 `spec-graph` 写入，顶层字段：

| 字段 | 含义 |
| --- | --- |
| `version` | 版本号 |
| `revision` | 单调递增修订号，`--expect-revision` 与之比对 |
| `stage` | `planning` → `implementing` → `reviewing` → `fixing` → `verifying` → `ready_to_deliver` |
| `inputs` | 需求.md、协议与数据.md、技术方案.md 的 sha256 与合并 `digest`；技术方案按剔除「## 交付状态」块后取摘要 |
| `candidate` | `cmd`、`internal`、`scripts`、`api`、`migrations` 与 `go.mod`、`go.sum`、`Makefile` 的 sha256 与合并 `digest` |
| `findings` | 审查发现列表，含 id、severity、status、note |
| `evidence` | 证据列表，含 kind、exit_code、recorded_at 与绑定的 candidate / inputs 摘要 |
| `events` | 阶段推进事件列表 |

## 七、接口
路由在 `internal/httpapi/handler.go`；错误统一为 `{"error":{"code":"...","message":"..."}}`，请求体上限 16 KiB，JSON 解码开启 `DisallowUnknownFields`。

| 方法与路径 | 响应 |
| --- | --- |
| `GET /healthz` | 200 `{"status":"ok"}` |
| `GET /v1/ping` | 200 `{"message":"pong"}` |
| `POST /v1/notes` | 201 `{"id","title","content","created_at"}`；校验失败 400 `invalid_argument` |
| `GET /v1/notes/{id}` | 200 同上；不存在 404 `not_found`；未预期错误 500 `internal_error` |
