## API 契约

> 与 `Specs/requirements/协议与数据.md` 一致；此处是实现层面的最终定义。

### POST /v1/notes

- 用途：创建笔记
- 鉴权：无
- 请求：`Content-Type: application/json`，体积上限 16 KiB，未知字段拒绝

```json
{"title": "买菜", "content": "鸡蛋、牛奶"}
```

- 响应 `201`：

```json
{"id": "n_9f1c2a7b3e4d", "title": "买菜", "content": "鸡蛋、牛奶", "created_at": "2026-09-07T02:00:00Z"}
```

- 错误：

| HTTP | error.code | 触发条件 |
| --- | --- | --- |
| 400 | invalid_argument | JSON 非法、含未知字段、请求体超过 16 KiB（message: `invalid request body`） |
| 400 | invalid_argument | `title` 缺失 / 空白 / 超过 100 字符（message: `title must be 1-100 characters`） |
| 400 | invalid_argument | `content` 超过 2000 字符（message: `content must be at most 2000 characters`） |

### GET /v1/notes/{id}

- 用途：按 ID 读取笔记
- 鉴权：无
- 请求：无请求体
- 响应 `200`：同创建响应
- 错误：

| HTTP | error.code | 触发条件 |
| --- | --- | --- |
| 404 | not_found | ID 不存在（message: `note not found`） |
| 405 | （ServeMux 文本响应） | 未定义方法，如 `DELETE` |

## 模块设计

| 包 | 职责 | 关键类型 / 函数 |
| --- | --- | --- |
| `internal/httpapi` | 路由、请求解析、响应编码 | `notesHandler{logger *slog.Logger; svc *note.Service}`：`create`、`get`；`decodeJSON` 限制体积、拒绝未知字段、拒绝首个 JSON 值之后的尾随数据；`ValidationError` -> 400，`note.ErrNotFound` -> 404，其他错误 -> 500 并用 logger 记录细节 |
| `internal/note` | 业务规则与端口接口 | `Note{ID, Title, Content, CreatedAt}`；`CreateInput{Title, Content}`；`Service{repo Repository; now func() time.Time; newID func() (string, error)}`：`Create(ctx, CreateInput) (Note, error)`、`Get(ctx, id) (Note, error)`；`Repository interface { Save(ctx, Note) error; Find(ctx, id) (Note, bool, error) }`；`ErrNotFound`；`ErrAlreadyExists`（Save 遇到已存在 ID 时返回，Create 以 `%w` 包装上抛）；`ValidationError{Field, Message}` |
| `internal/memstore` | 存储实现 | `Store`（`sync.RWMutex` + `map[string]note.Note`）实现 `note.Repository`；`New()`；`Save` 对已存在 ID 返回 `note.ErrAlreadyExists`，不覆盖 |

数据流：`POST /v1/notes` -> `notesHandler.create` 解码并调用 `svc.Create` -> `Service` 去空白、按 `utf8.RuneCountInString` 校验、生成 `n_` + 12 位小写十六进制（`crypto/rand` 6 字节）、`now().UTC()` -> `repo.Save` -> 201 JSON。`GET /v1/notes/{id}` -> `r.PathValue("id")` -> `svc.Get` -> `repo.Find`，未找到返回 `ErrNotFound` -> 404 信封。`cmd/api` 创建 `memstore.New()` 与 `note.NewService(store)` 并传给 `httpapi.NewHandler(logger, svc)`。依赖方向 `cmd -> httpapi -> note <- memstore`。

## 风险与回滚

- 内存存储在进程重启后丢失全部数据：需求已声明，README 与技术讲解写明「演示用途」
- 请求体上限 16 KiB 由 `http.MaxBytesReader` 保证，超限统一映射为 400 而不是 413（与协议约定的错误码表一致，413 未在表中）
- ID 生成依赖 `crypto/rand`：Go 1.24 起 `rand.Read` 不返回错误，真实故障表现为进程崩溃并由进程管理器重启；`Service.newID` 的 error 返回值只作为测试注入接缝保留（`TestService_Create_IDGenerationFails`）
- 同一进程内 ID 冲突概率可忽略（48 位随机）；即使发生，`Store.Save` 返回 `ErrAlreadyExists` 而不是覆盖，HTTP 层返回 500 并记录日志
- 回滚：删除 `internal/note`、`internal/memstore`、`notesHandler` 与两条路由，撤销 `cmd/api` 装配；无数据迁移需要回退
